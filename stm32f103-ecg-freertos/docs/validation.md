# 2026-09-13 验证记录

## 软件构建

GNU Arm Embedded 13.3.1，C11，Cortex-M3/Thumb，-Os，-Wall -Wextra -Werror。

- Flash：7832字节 / 65536字节。
- RAM布局：18912字节 / 20480字节，包括全部用户任务/Idle静态栈和TCB，以及1024字节主中断栈预留。
- 链接脚本校验至少有1KB主栈空间；剩余布局余量1568字节，不宜随意增大任务或缓存。
- Windows原生GCC构建上位机、串口实板测试和公共模块测试成功；所有应用源文件为C。
- 上位机导入的DLL只有Windows系统库：comdlg32、GDI32、KERNEL32、msvcrt、USER32。无Python/Qt/MinGW运行库DLL依赖。

## 本机C测试

test_core.exe四组测试全部通过：

1. CRC16已知向量、错包后重新同步、帧形状检查、小端编码。
2. 三通道ADC平均、历史环绕、过期和未来区间。
3. 连续产生6000组记录，5秒全丢、周期丢包、补传丢失、重试后6000组逐点一致；重复包不重复计数。
4. 会话隔离、历史过期、有界缺包请求和100ms重试超时。

test_session.exe另行验证未连接时拒绝CSV且不创建文件、停流3秒后提示超时、主动丢弃5秒期间抑制超时提示，全部通过。

这些测试执行实际共享C实现，不是另外写一套Python模型。但它们不模拟MCU外围寄存器。

## ST-Link烧录

检测到STLINK V2J37S7，Cortex-M3，64KiB Flash，板电压约3.25V。OpenOCD执行下载、verify、reset成功，日志为Verified OK。板上已运行本版本。

## 实板5秒断传测试

使用C程序board_test.exe，经COM7 / 115200 / 8N1连接实际板子。整个测试16秒，第2秒开始丢弃接收5秒。测试期间ADC任务继续运行，之后选择性补传。

最终一次结果见board_test.json：

| 指标 | 结果 |
|---|---:|
| 应收到的连续序号记录数 | 3975组 |
| 实际唯一记录数 | 3975组 |
| 待补 / 过期 | 0 / 0 |
| 故意丢弃的接收字节 | 9250 |
| ADC故障 / RX错误 / CRC或帧错误 | 0 / 0 / 0 |
| ADC / 通信 / 监测任务优先级 | 4 / 2 / 1 |

| 采集任务最大处理耗时 | 180 µs |

这里“字”为32位，即884 / 1452 / 540字节。统计是本次运行观察值，不是形式化的最坏执行时间保证。前一轮同版本架构测试也为3975组完整、0错误；最终构建增加了共享统计的volatile声明。

此前裸机版实板测试的最终记录有950组缺口和8次RX错误。本版本实测通过，不以之前裸机软件测试结果代替实板结论。

## 边界

- 测试的是人工丢弃接收字节，不是拔掉板子供电；掉电不能恢复RAM历史。
- 板子三路确实通过跳线进入ADC；并非人体电极采集。未验证模拟心电的临床准确性。
- 尚未完成长时间老化、所有串口错误模式、低电压/时钟扰动、所有任务阻塞组合测试。
- 6.4秒是原始缓存容量；实际可恢复中断长度还取决于恢复延迟和有效吞吐。
